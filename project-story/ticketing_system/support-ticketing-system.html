Project Story

Support Ticketing System

A web-based enterprise ticketing system designed to organize customer support requests, complaints, and incidents through clear workflows, role-based interfaces, and structured information.

01 — The Challenge

Turning Support Complexity into a Clear Workflow

The project addressed the challenge of managing customer support requests, complaints, and incidents across different departments and operational roles. Without a structured workflow, information could become difficult to route, track, and monitor.

The goal was to create a centralized experience that could make the movement of a ticket easier to understand and manage — while giving each user role the information and actions relevant to its responsibilities.

02 — My Role

Leading the User Experience & Interface Design

This was a team-based graduation project. I led the GUI and interface design, taking responsibility for the front-end user experience across the system's different roles.

I also contributed to the data structure and relational modeling, which helped me understand how the underlying information and relationships should translate into usable interface structures.

  • Lead UI/UX design and GUI architecture
  • User experience and interface design across four roles
  • Information structure and screen organization
  • Dashboard layouts, navigation, and interaction patterns
  • RTL interface design and visual consistency
  • Contribution to data structure and relational modeling
  • Visual documentation, user guides, and presentation design
03 — Understanding the System

Before Designing the Interface, Understand the Flow

The interface was designed around an understanding of how information moves through the system. A ticket can originate with a customer, move through operational teams, be assigned and processed, and ultimately reach resolution and closure.

04 — From Data Structure to Interface

Understanding the Structure Behind the Screens

The system depended on relationships between users, roles, tickets, departments, assignments, branches, and supporting information. Understanding these relationships helped shape the information architecture and the way users interact with the system.

System Thinking

Structure Informs Experience

My contribution to the data structure and relational modeling gave the interface design a stronger connection to the actual system logic — helping translate structured information into screens, navigation, and user actions.

05 — Designing for Different Roles

One System. Four Different Experiences.

The system served four main user roles — Customer, Operator, Agent, and Administrator. Each role required a different level of information, different actions, and a different way of interacting with the ticket lifecycle.

Rather than treating the interface as one generic experience, the screens were structured around the responsibilities and information needs of each role.

06 — The Interface

Designing the Operational Experience

The interface brought together navigation, operational actions, status indicators, KPIs, and data views into a role-focused experience. The design used a clear visual hierarchy to help users identify what requires attention and move through the workflow efficiently.

07 — Visualizing Operations

Making Status and Performance Visible

The administrator experience used KPI cards, status summaries, charts, tables, and action controls to turn operational information into visual signals that could be understood quickly.

New, in-progress, delayed, and closed tickets were given distinct visual treatment, helping users recognize the current state of operations without having to interpret every record individually.

08 — From Design to Delivery

Designing Beyond the Screen

The work extended beyond interface design into documentation, user guidance, testing, and final project presentation. Visual layouts and step-by-step guides were developed to help explain the system and support its delivery.

This broader involvement helped connect the interface design with the complete project experience — from understanding the system and structuring information to communicating and presenting the final solution.

09 — The Result

A Structured Digital Experience for Complex Workflows

The final solution brought customer support processes, operational workflows, role-based interfaces, structured information, and management visibility together within one digital experience.

From a creative perspective, the project demonstrates how understanding the system, its data relationships, and its users can lead to clearer interfaces and more meaningful digital experiences.
